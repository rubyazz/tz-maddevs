# Промпты и процесс работы с AI-агентами

Проект делался с AI-агентами (задание прямо это ожидает и просит не
скрывать). Инструмент: **Claude Code CLI** (терминальный агент-оркестратор),
модель-двигатель уточняется инструментом; оркестратор планировал, писал
бэкенд-домен и инфраструктуру, координировал субагентов и делал интеграцию.

Ниже — ключевые промпты. Полный экспорт сессии лежит рядом (файл
`session_export.jsonl`, прикладывается отдельно) — в нём видны и временные
метки хода работы.

---

## 0. Исходное задание (заказчик)

> Требования одинаковы для всех заданий.
> 1. Клиент-серверный продукт: отдельный backend и отдельный frontend, общаются по сети.
> 2. Backend: Python, Go или Node.js…
> 3. Frontend: Vue или React.
> 4. Хранилище: реляционная СУБД… предпочтительно PostgreSQL.
> 5. Учётные записи и вход — на ваше усмотрение…
> 6. Промпты или лог решений сдаются вместе с кодом…
> 7. Использование AI-агентов ожидается…
> 8–13. …локальный запуск, эмуляция внешних сервисов, два одновременных
> клиента, честное описание состояния, доказуемость.
>
> Задание «Монитор доступности сайтов»: список проверок (URL, интервал
> 30с–1ч, таймаут, ожидаемый код, опционально строка в теле), группы с общим
> статусом, панель текущих статусов, история (график времени ответа и %
> доступности за сутки/неделю/месяц), журнал инцидентов, окна обслуживания,
> настройки оповещений (почты на группу), публичная страница статуса без
> входа. Поведение: статусы меняются сами; письмо на падение и на
> восстановление, между ними — тишина; кратковременный сбой не падение
> (порог наш); в окне обслуживания письма не уходят, но по концу окна при
> живом падении — уходят; проверка не запускается параллельно сама с собой;
> 50 проверок × 30с не мешают друг другу; история за месяц открывается
> быстро; публичная страница показывает только разрешённое; после рестарта
> проверки продолжаются, простой — дыра в истории, не падение.

+ Указание заказчика по стеку (черновик): «Python + Django/DRF +
PostgreSQL + Redis + Celery + asyncio/httpx + React/TypeScript + Docker
Compose… maybe fastapi, but do it like in production level… use team of
agents… for front u can use impeccable skill… dont forget about task
criterias».

## 1. Промпт оркестратору (постановка на сессию)

Кратко: спроектировать и собрать production-уровень монитор доступности
сайтов по ТЗ выше; рекомендовать и обосновать стек (заказчик склоняется к
Python, допускает FastAPI); использовать команду субагентов; для дизайна
фронтенда — Impeccable skill, для графиков — dataviz skill; коммитить по
фичам/доменам; вести DECISIONS.md с метками времени; все критерии задания
закрыть и доказать (PROOF.md).

## 2. Промпт субагенту «Backend» (дословно существенное)

> Прочитай docs/CONTRACT.md в репозитории — это единственный источник правды
> (схема БД, API, доменные правила шедулера/инцидентов/окон). Реализуй
> backend/ строго по контракту: FastAPI + SQLAlchemy 2 async + Alembic +
> PostgreSQL + Redis. Файлы только внутри backend/ и tests/. Не выдумывай
> эндпоинты/поля, которых нет в контракте. Пароли argon2, JWT HS256,
> валидация pydantic v2, границы интервалов 30..3600 и таймаутов 1..30 — и в
> схеме, и в CHECK-констрейнтах. Код — как продакшен: типизация, docstrings,
> без print, логирование structlog/stdlib. Верни список созданных файлов и
> что не успел.

## 3. Промпт субагенту «Frontend» (дословно существенное)

> Прочитай docs/CONTRACT.md (API, JSON-форматы, SSE-события) и секцию
> «Design direction» в конце. Собери frontend/ на React 18 + TypeScript +
> Vite + TanStack Query v5 + React Router + Tailwind + Recharts. Страницы:
> Login/Register, Dashboard, Check detail (графики+инциденты), Group
> (emails, публичность), Maintenance, Mailbox, Demo (управление эмулятором),
> публичная /status/:slug. SSE через EventSource(/api/events?token=…):
> любое событие → invalidate соответствующих query. Никаких моков данных —
> только реальный API. Следуй дизайн-направлению (палитра, статусы, пустые
> состояния, тёмная тема). Файлы только внутри frontend/.

## 4. Промпт субагенту «Tests»

> Покрой тестами (pytest, pytest-asyncio, httpx AsyncClient, respx для
> HTTP-моков): машину состояний инцидентов (порог, закрытие, письма
> ровно по одному), suppression окнами обслуживания, claim
> (in_flight_until) — параллельный запуск невозможен, валидацию API,
> агрегацию истории. Тесты БД — против отдельной test-БД в compose.

## 5. Промпт субагенту «Review»

> Отревьюй diff на соответствие CONTRACT.md и критериям задания; найди
> расхождения контракта и реализации, гонки в шедулере, дыры в авторизации
> (IDOR на группах/проверках/окнах), утечки в публичном SSE.
