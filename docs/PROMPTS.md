# Промпты и процесс работы с AI-агентами

Инструмент: **Claude Code CLI** (модель GLM-5) — один агент-оркестратор
планировал, писал код и интегрировал; спавн субагентов в этой сессии был
недоступен (инструмент Agent не exposнут), поэтому «команда» — это
оркестратор + скиллы (dataviz для графиков, run для браузерной проверки).
Процесс не скрывается; полный экспорт сессии (jsonl) прикладывается рядом с
этим файлом.

## Исходный промпт (суть)

ТЗ «Монитор доступности сайтов» + общие требования (клиент-сервер, Python/
Go/Node, Vue/React, реляционная СУБД, эмуляция внешних сервисов, два
одновременных клиента, честное описание, доказуемость, промпты и лог
решений сдаются, ход работы во времени по коммитам). Указания заказчика по
стеку: Python + Django/DRF + PostgreSQL + Redis + Celery + asyncio/httpx +
React/TS + Docker; «maybe fastapi, but do it like in production level»;
«use team of agents»; для фронта — impeccable skill; uv для пакетов, pytest
для тестов; коммитить по фичам; покрыть unit+integration тестами и написать
CI (lint/test/build для обеих сторон).

## Ключевые промпты оркестратору (по ходу)

1. Спроектировать production-уровень монитор по ТЗ, рекомендовать стек,
   зафиксировать CONTRACT.md как источник правды, вести DECISIONS.md с
   метками времени, коммитить по доменам.
2. Перед графиками — dataviz-скилл (дистиллирован в §9 контракта:
   hex-токены, спецификации марок, тултипы, «статусный цвет не один»).
3. По репорту «синий фон на /demo» — воспроизвести в headless-Chromium,
   снять консоль и DOM-аудит, починить, перепроверить.
4. Финал: STATE.md (честное состояние), PROOF.md (сценарии с выводами),
   README с быстрым стартом.

## Ход работы во времени

Виден по истории git-коммитов (21 коммит за ~2.5 часа, метки в git log) и
этому журналу; экспорт сессии — отдельным файлом.
